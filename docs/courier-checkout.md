# 快递结算（2026-11-16）

本轮为本地实现。部署前需要一起发布前后端并运行迁移 `0036_courier_checkout`，不代表已上线或已完成真实收款验收。

## 价格与后台

「价格与套餐 → 每单快递运费」配置 USD 固定金额。迁移仅在没有此类型记录时初始化 USD 0.00，不覆盖已有记录。每种类型最多一个启用价格。停用该类型会关闭新快递订单，已有订单仍按冻结报价付款。订单总额为启用的单次打印价格＋每单快递运费，数量固定 1；AI 额度不重复收费。

非零快递订单必须有可用 Stripe／Airwallex 渠道，总额须为 USD 0.50–999999.99。打印价格为 0 时仍按配置收取运费；打印和运费均为 0 时使用 free_test 免付测试确认，不调用支付渠道、不伪造实际收款。此测试订单与现场设备隔离。直连模拟环境禁止快递支付。

## 接口

- `GET /api/v1/store/payment-config/?fulfillment_type=courier` 返回对应线上支付渠道和 `quote`：`version:1`、`currency`、`print_amount`、`shipping_amount`、`total_amount`（金额为两位小数字符串）。缺少启用价格返回 409；渠道不可用返回 `available:false`。不带参数的现场自取配置保持兼容。
- `POST /api/v1/store/orders/` 沿用订单访问密钥、身份、同意、单份及设计快照验证。快递传 `fulfillment_type:courier`，增加 `delivery_address`：`recipient`、`phone`、`region`（国家／州／城市）、`street` 必填，`postal` 选填；`expected_amount` 是包含运费的总额。服务端锁定价格后重新计算，前端不能指定运费或折扣。价格变化返回 409 供用户重新核对。
- 创建后冻结 `delivery_address`、`shipping_quote` 及订单总额。相同 `request_key` 重试返回原订单；改变地址或配送方式不会覆盖旧订单，返回 409。断网／响应丢失时继续使用原 key，不盲目另建。
- 订单详情按原浏览器访问权返回地址及报价；列表不返回地址。后台授权订单详情只读展示地址和冻结费用，不允许通过通用修改接口改价／改址。前端本机草稿保存在原身份的私有空间；确认订单时才向后端传递地址。
- 付款复用 `/orders/{reference}/checkout/`，按冻结总额创建渠道会话／Intent，超时重试保留相同渠道幂等标识。渠道通知依原有签名、金额、币种与身份核验确认到账；浏览器返回页不构成付款成功。取消、退款中订单及缺少有效冻结地址／报价的历史快递单拒绝付款。

## 配送边界

付款成功后客服可在后台查看订单设计、收件信息及费用，另行安排生产和快递配送。未接入承运商下单、追踪号码或物流状态自动同步，不展示虚构的 3–4 天时效。快递不调用现场设备绑定、设备文件上传、供应商推单或立即打印；所有原有设备隔离检查保留。空运新选择入口移除，历史订单与金额不改写。
