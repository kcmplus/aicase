# Codex CLI 持续执行 harness

这个本地执行器把一个有明确验收标准的任务交给产品、开发、测试三个角色，重复执行到验收通过、遇到阻塞或达到运行限制。它不会自动领取其他任务，也不会因为模型说“完成”或进程退出码为 0 就认定业务完成。

首版执行器使用 Python 3 标准库，面向 macOS/Linux；运行锁和进程组停止依赖这些平台的能力，不支持 Windows 原生运行。业务测试仍使用仓库已有 Python 虚拟环境、Node.js 与相应依赖。

## 角色与执行顺序

| 角色 | 固定模型 | 责任 |
| --- | --- | --- |
| 产品 | `gpt-6-astra` | 核对目标、范围、现有能力和验收证据，确定本轮最小完整工作 |
| 开发 | `gpt-6.1-sol` | 根据产品要求及上一轮测试反馈改动代码，报告改动与验证 |
| 测试 | `gpt-6.1-terra` | 独立检查结果、补充或修改测试、执行验证、逐项说明验收证据或缺口 |

先运行产品规划，再按开发 → 测试 → 固定 gate → 产品复核循环；测试或 gate 未通过时直接进入修复轮次。同一时刻只有一个角色执行；业务源码由开发角色修改，测试角色可以补充或修改测试，产品负责检查与报告。测试进程可产生正常的临时输出。执行器独立运行任务文件中固定的 `gates`，防止只依赖模型自行报告测试通过。失败反馈进入下一轮，不能靠删除断言或放宽任务要求通过验收。

### 职责与交接条件

每次启动 agent 都会注入对应的职责约定，明确允许的工作、交付内容与停止条件。完整任务描述用于理解背景，不授予单个 agent 包办整个流程的权限。

| 阶段 | 应交付的结果 | 边界与交接 |
| --- | --- | --- |
| Astra 产品规划 | 现有能力、缺口、按验收项拆出的开发步骤 | 只读，不实现功能、不编写测试、不运行整套验收；输出规划后交开发 |
| Astra 产品决策（按需） | 对开发/测试的问题给出选择、依据、假设和执行建议 | 只读，任务内可逆选择自行决定；不代替用户授予新权限，决定后返回提问角色 |
| Sol 开发 | 实现、必要开发测试及自测结果、交测说明 | 可以自测，但不能代替独立 QA 或宣布最终完成；实现后交测试 |
| Terra 测试 | 独立测试用例、逐项证据、缺陷复现步骤和实际/期望结果 | 可以修改测试文件，不能修复生产代码；发现缺陷交回开发，不能自行修好后宣布通过 |
| Astra 产品复核 | 按冻结验收项逐项审查代码、QA 报告和本轮 gate 结果 | 只读，不接管开发或测试，不放宽标准；输出复核结果后交回 harness |
| harness 调度 | 阶段调度、固定 gate 执行、最终状态 | 唯一有权进入下一阶段、启动修复轮次和写入 `complete` 的组件 |

规划阶段只能返回 `revise`（规划就绪、交给开发）或 `blocked`，不能返回验收 `pass`。其他阶段的 `pass` 只代表**本角色交付通过**：开发的 `pass` 仍必须经过独立测试、固定 gate 和产品复核。每个阶段使用限定角色的报告结构；冒用其他角色的报告会被拒绝。

所有 agent 都必须在交付本阶段报告后结束，不得自行调用 Codex、子代理或 harness 启动后续流程。`next_actions` 是交接清单，不是让当前 agent 继续执行其他角色工作的指令。

### 产品负责人承接问题

产品角色不仅负责开始规划和最后验收，也负责执行中出现的产品疑问。规划时应主动补齐任务内可逆的细节，依据现有产品约定选择一致的默认方案，说明假设，避免将普通选择推回用户。

开发或测试确实需要产品判断时，通过结构化报告返回 `verdict=needs_product`：`summary` 写问题、上下文和影响，`next_actions` 写候选方案与推荐方案。它们不调用用户提问工具、不等待聊天回复，也不继续执行依赖该答案的工作。harness 会调用只读的 `product-decision` 阶段，再把答案交回原角色：

```text
开发提问 → Astra 产品决策 → 开发继续 → 独立测试 → gates → 产品验收
测试提问 → Astra 产品决策 → 测试继续 → gates → 产品验收
```

产品可决定文案、交互、任务内默认值和边界行为等可逆选择；普通编码与测试方法仍由相应执行者自行决定。回答使用 `verdict=decided`，`summary` 记录决定、依据和假设，`next_actions` 提供明确执行建议。产品决定不是通过验收，不能跳过开发、独立 QA 或固定 gate。

产品不能扩大冻结范围、放宽验收、捏造供应商事实或代替用户授予账号、资金、部署、硬件等权限。确实缺少授权、凭证、外部事实时仍返回 `blocked`，说明具体缺口；开发/测试明确报告的此类 `blocked` 也不会转成产品自动批准。阶段模型对问题性质的分类与答案内容依赖提示和复核，程序无法自动证明每个业务决定都正确。

决定和原始问题保存在运行状态的 `product_decisions`，所有后续角色和恢复后的会话都会收到记录；未解决的问题保存在 `pending_question`。同一角色重复提交已回答的相同问题文本会停止；每次进入一个角色阶段最多进行 3 次产品问答，避免无限往返。达到限制不会标记完成。自然语言提问若未遵循报告结构，仍按无效报告停止，不会猜测答案后继续。

职责约定由提示和执行检查共同约束：产品使用只读权限；执行器比较阶段前后的文件指纹，产品修改源码或测试员修改非测试文件时会停止并使验收失效。测试文件按路径规则识别，指纹覆盖 Git 已跟踪及未被忽略的文件，不是完整的操作系统文件权限隔离。越界检查发生在阶段结束后，不会自动回滚改动；需要检查日志和差异后再恢复。禁止嵌套调度、不得弱化测试等语义规则依赖角色提示及后续复核，不能宣称程序能拦截所有越界动作。

模型名称按用户选择固定，不在不可用时自动替换。官方资料说明 `codex exec` 支持非交互调用、JSON 事件流和结构化最终输出，执行器据此保存过程与结果：[Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)。三个模型的公开名称见 [OpenAI 模型目录](https://developers.openai.com/api/docs/models)。具体账号权限、额度及本机客户端能否调用，仍需实际验证；公开目录不是账号可用性证明。GPT-6.1 Terra 要求 Codex CLI 0.159.0 或更新版本，见 [Codex 模型说明](https://learn.chatgpt.com/docs/models)。

## 启动与停止

从仓库根目录执行。先查看任务文件并运行演练：

```sh
python3 scripts/codex_harness.py run \
  --task harness/tasks/direct-debug-acceptance.json \
  --dry-run
```

`--dry-run` 用于检查任务和执行计划，不运行三模型业务任务，也不证明模型账号可用或验收通过。正式启动命令：

```sh
python3 scripts/codex_harness.py run \
  --task harness/tasks/direct-debug-acceptance.json
```

默认最多 **8 轮、4 小时**。可以明确调整限制：

```sh
python3 scripts/codex_harness.py run \
  --task harness/tasks/direct-debug-acceptance.json \
  --max-cycles 12 --max-seconds 21600
```

`--max-cycles 0` 表示不限制轮数，默认 4 小时时间限制仍生效。`--max-seconds 0` 表示不限制总时间；同时设置二者为 0 才会取消轮数和总时长上限。单次模型调用仍有超时限制。这不保证任务一定成功；账号限流、缺失依赖、外部阻塞或手动停止都可能提前结束。长期运行会持续消耗账号额度。

启动后保留执行器给出的运行目录。以下 `PATH` 替换为该目录：

```sh
python3 scripts/codex_harness.py status --run-dir PATH
python3 scripts/codex_harness.py stop --run-dir PATH
python3 scripts/codex_harness.py resume --run-dir PATH
```

`status` 查看已有状态；`stop` 写入停止请求，运行者检测后终止当前进程组并记录 `stopped`；`resume` 使用原任务快照，从新的产品规划和开发轮次重新验证。恢复不会回滚之前的代码改动，也不沿用旧测试报告直接判定通过。每次恢复默认重新给予 8 轮、4 小时预算，可使用同名限制参数调整；因此多次恢复的总消耗可能超过首次启动限制。修复缺失依赖或账号问题后，应先检查状态与日志再恢复。

## 工作区与授权边界

执行器默认拒绝在已有未提交改动的工作区开始。明确接受保留当前改动后，可追加 `--allow-dirty`；演练时同样可以使用它。该选项允许基于当前工作区继续，不表示这些改动属于执行器或可以覆盖。

本仓库当前存在大量原有未提交改动。选定示例任务后，如继续使用当前工作区，实际启动命令应带 `--allow-dirty`；先检查并保留起始基线：

```sh
python3 scripts/codex_harness.py run \
  --task harness/tasks/direct-debug-acceptance.json \
  --allow-dirty
```

只检查执行计划时追加 `--dry-run`：

```sh
python3 scripts/codex_harness.py run \
  --task harness/tasks/direct-debug-acceptance.json \
  --allow-dirty --dry-run
```

执行器不自动 stash、推送或发布；默认不提交，用户明确启用 `--git-checkpoints` 时按下述规则创建本地检查点。开始前记录工作区基线，报告应区分原有改动与本轮改动。长任务运行时避免在同一工作区同时进行其他编辑；中断后不要通过重置工作区“清理”用户原有内容。

任务约束与角色提示是执行边界的一部分，不能替代操作系统、网络及账号权限隔离。不得因为写进 JSON 就宣称真实供应商网络已经被系统阻断。对业务外网完全禁用的任务，验收实现必须提供对应的 mock/阻断和证据；本地测试也不得使用真实密钥。

## 任务文件与完成依据

任务是版本为 `1` 的 JSON，包含稳定的 `id`、`title`、`goal`，以及以下字段：

| 字段 | 用途 |
| --- | --- |
| `scope` | 可改范围及本轮完整目标 |
| `constraints` | 数据、外部操作、跨仓库和验证边界 |
| `acceptance` | 带唯一 `id` 的逐项验收描述 |
| `gates` | 固定命令：`argv` 参数数组、相对仓库的 `cwd`、单项超时秒数 |
| `models` | 产品、开发、测试的固定模型 ID |

命令参数使用数组，避免把一段 shell 字符串当作验收配置。固定 gate 是最低回归要求；它通过不等于所有验收项完成。浏览器流程、截图、数据不变性等要求，仍须提供对应的实际执行证据。

验收报告包含 `role`、`verdict`、`summary`、`criteria` 和 `next_actions`。`criteria` 按每个验收 ID 各列一项 `status` 与非空 `evidence`；证据应说明执行命令、隔离数据、实际结果及文件位置。只有测试和产品复核均为通过、每项验收通过且固定 gate 全部成功，运行才记为 `complete`。结构检查不能判断一段证据是否真实，因此产品和测试仍必须实际核对记录，不能只写“通过”。

状态包括 `running`、`complete`、`blocked`、`error`、`interrupted`、`stopped`、`limit_reached`。缺少证据、命令失败、模型返回格式错误、超时、账号不可用或依赖缺失不能写成成功。可在当前范围内修复的失败进入下一轮；需要用户输入或越过边界的情况报告阻塞，不无限重复同一失败。

执行器把记录保存在 `.codex-harness/runs/<运行标识>/`，该目录已忽略提交。`task.json` 与 `task.sha256` 冻结任务；`status.json` 与 `events.jsonl` 保存状态和历史；`baseline-status.txt`、`baseline.diff` 记录起始工作区。各阶段位于 `stages/`，保存 `prompt.txt`、`report.json`、模型事件与 `stderr.log`，固定 gate 保存命令输出日志。恢复依赖这些记录，而不是只依赖聊天记忆。运行日志可能包含仓库内容和测试输出，仅保留本地；不提交数据库、认证信息、客户图片或运行日志。

## 示例任务：本地直连模拟验收

示例为 [direct-debug-acceptance.json](../harness/tasks/direct-debug-acceptance.json)。用户本轮明确只交付通用 harness 和示例任务；未启动该任务的业务开发与验收。上面的启动命令用于后续明确选择任务时执行。

当前工作区已有独立调试配置、数据库副本、零元订单、`direct_debug` 传输、受权限保护的轮询/预览、手机确认和模拟状态，详见 [后端直连调试](direct-terminal-debug.md)。已有 `test_direct_terminal.py` 等用例也覆盖部分幂等与隔离能力。示例目标是补齐可重复的浏览器端到端验收并修复实际发现的问题。

示例限定在本仓库改动，`../aicase-terminal` 只读；禁止真实供应商调用、支付、退款、库存同步、硬件控制、部署及推送。手机端与设备页使用合成图片和隔离本地数据，必须区分模拟打印/出货与真实打印/领取。

前两个固定 gate 的文件与命令入口已按当前工作区核对：

```sh
backend/.venv/bin/python backend/manage.py test \
  management_api.test_direct_terminal \
  management_api.test_supplier_orders \
  management_api.test_supplier_payments \
  management_api.test_fulfillment \
  --settings=config.settings --noinput

node --test frontend/tests/fulfillment.test.mjs \
  frontend/tests/order-service.test.mjs \
  frontend/tests/device-info.test.mjs
```

Django gate 使用测试数据库和用例内的调试设置覆盖，不运行真实供应商联调。第三个 gate 是 `node scripts/test-direct-debug-e2e.mjs`，该脚本当前尚不存在，明确要求由候选任务实现并通过；这样只通过旧回归用例无法完成新验收。该入口必须自给测试数据、自动启动与清理服务，实际完成手机浏览器下单到模拟完成的路径，并留存证据。如果现有终端或浏览器条件不支持安全自动化，应报告阻塞，不能跳过 gate。

现有 `npm run backend:direct -- --check` 会准备或更新调试副本，不能当成完全只读检查，也不能代替端到端验收。手工手机操作说明未执行时只能作为复现步骤；现有集成测试的 mock 返回不能证明浏览器、真实设备或部署通过。

## 功能分支与自动 Git 检查点

2026-11-14 用户授权每次大修改记录本地提交。新版 UI 启动脚本已默认启用 `--git-checkpoints`，并检查当前分支包含 `origin/main`。通用 harness 默认仍不自动提交。

启用时仅允许 `codex/` 功能分支，开始新运行前要求干净基线；`--allow-dirty` 不能绕过，缺少 Git 身份或处于主分支/游离 HEAD 会停止。先前的脏工作区示例仅适用于没有启用此功能的通用任务。

开发按有边界的功能组自测后交接；开发和测试各次有效报告返回后，harness 对变化创建本地检查点，记录任务、阶段、轮次和对应运行目录。没有变化不创建空提交。报告为 revise 或 blocked 时的检查点也只表示保存版本，不表示通过；仍须独立 QA、固定 gates 和产品验收。最终状态记录 `accepted_commit`，与 `events.jsonl` 的阶段提交记录关联。

提交只由 harness 发起，agent 不自行暂存/提交/切换分支。产品只读阶段不提交。QA 后若源码变化仍使原验证失效；创建检查点后使用新指纹继续验证。发现预先暂存的内容、常见凭证/数据库/运行产物路径、疑似密钥、符号链接或过大文件时停止并保留文件，不绕过提交钩子、不自动撤销已有暂存。

常见敏感路径和字符串检查不等于完整秘密扫描，仍须审查变更和遵守私有素材边界。检查点提交失败、钩子改变源码或分支变化时不能记为完成。异常中断保留未提交工作；resume 沿用检查点策略，在原功能分支重新规划和验收，不自动 reset。手动修正后恢复时，新一轮检查点也会纳入此前留下的未提交修改，因此不要混入无关工作。

本地验证：26 项 harness 黑盒测试通过，新增覆盖阶段提交与验收提交号、主分支/脏基线拒绝、敏感文件拒绝、失败后恢复和不重复空提交。未运行真实业务迁移。

## 实时对话与执行输出

默认在终端实时显示 agent 的公开进度说明、工具操作/结果、文件修改、错误，以及固定检查的输出；最终结构化交接报告转换成「结论、逐项证据、下一步」显示，不直接刷 JSON。沿用 [Codex CLI JSON 事件流](https://learn.chatgpt.com/docs/non-interactive-mode) 和本机实际事件格式，不展示内部 reasoning 事件，不保证逐 token 输出；上游产生公开消息后才会显示。

日志继续完整保存在各阶段 `events.jsonl`、`stdout.log` 和 `stderr.log`。终端上的长工具输出会截短并提示，完整内容仍留在日志。显示层去除终端控制字符，不修改原始日志和报告；未知事件忽略，残缺 JSON 留在原文件，避免影响验收。

`run` / `resume` 默认启用；追加 `--quiet` 可仅显示阶段、心跳和最终状态，日志仍保留。旧运行记录没有此设置时，恢复默认启用实时显示。该选项不改变冻结任务、角色分工、Git 检查点或验收规则。

本次中断的 UI 任务可直接使用 `bash scripts/run-ui-harness.sh resume`，无需新建运行。恢复从新的产品规划开始，保留旧日志与代码；工具不会在更新显示功能时自动恢复用户任务。

验证：29 项黑盒/显示测试通过，覆盖进程结束前实时可见、quiet 模式、UTF-8/JSON 分段、终端控制字符过滤及原有调度/检查点行为；另以实际中断运行的日志回放验证公开消息和工具事件。未自动恢复真实任务。
