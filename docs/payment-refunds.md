# 后台整单退款

在「打印订单」打开订单详情，超级管理员可填写原因并确认原路退回订单全额。支持已付款的 Stripe / Airwallex 测试及正式订单；演示、待付款、取消订单不支持。正式退款使用订单创建时冻结的渠道、环境和收款账户，不受后来切换渠道影响。

当前每个订单最多一笔后台退款申请，不支持部分退款。打印中或已交付订单允许管理员确认退款，但不会自动停止设备或收回商品。订单履约状态保留，退款状态单独展示；C 端退款订单不再显示付款和打印凭证入口。

## 配置

- Airwallex 账户级 Payment Acceptance 需有退款创建和查询权限，保留原支付通知地址，追加 `refund.received`、`refund.accepted`、`refund.settled`、`refund.failed`。
- Stripe 密钥需能创建/读取 Refund、读取 PaymentIntent，原支付通知地址追加 `refund.created`、`refund.updated`、`refund.failed`。
- 后台支付配置页面显示完整事件清单。服务端部署不会自动修改渠道里的通知订阅。

## 状态和重试

- 待核实：申请已持久化，尚未确认渠道是否受理（包括超时）。先点击「刷新退款状态」，查不到时可「重试提交」，复用原请求编号、金额和原因。
- 退款处理中：渠道已受理，等待确认。Airwallex `RECEIVED`、Stripe `pending/requires_action` 显示此状态；Stripe requires_action 需在渠道后台核对是否有额外处理要求。
- 已退款：Airwallex `ACCEPTED/SETTLED` 或 Stripe `succeeded`，通过渠道查询确认。此状态不保证顾客银行即时入账。
- 退款失败：渠道明确返回失败或取消，请在渠道后台核对。当前不提供创建第二笔退款申请；失败处理及人工对账须单独进行。

创建申请先提交数据库，再联系渠道。订单行锁、订单唯一退款记录和固定幂等键共同避免并发/超时重复退款。未得到渠道编号的请求超过 23 小时后禁止重新创建，只能查询核对；不会生成新幂等键。若渠道已有其他有效退款记录，停止整单退款，要求人工核对，避免与渠道后台操作冲突。

退款通知验证原始签名后，使用原订单凭据查询渠道真实状态，再校验退款编号、付款编号、金额、币种和关联信息。通知只同步本系统创建的退款，不根据渠道外退款通知自动创建退款单。接口错误保留待核实状态，不推断退款失败，也不泄露渠道原始错误或凭据。重复通知不重复记账。

## 接口与验证

- `POST /api/v1/admin/orders/{订单数字 ID}/refund/`：超级管理员、Session/CSRF，`revision`、`confirmed: true`、`reason`（1–128 字）；金额由后端锁定订单决定。
- `GET /api/v1/admin/orders/{订单数字 ID}/refund/`：超级管理员查询并同步；绝不触发退款创建。
- 订单列表展示独立退款状态；详情展示金额、原因、编号、退款确认时间。顾客订单接口只返回公开退款状态，不暴露内部原因或凭据。
- 迁移 `0020_printrefund`。自动化验证覆盖权限、CSRF、重复提交、请求中断、渠道记录核对、签名、金额匹配及两个渠道的接口参数；不调用真实退款。
- 上线后需配置商户通知订阅，使用授权的测试订单验收异步退款、余额不足及真实到账。当前没有定时退款查单任务，通知失败可使用后台「刷新退款状态」补偿。

官方接口：[Airwallex Refunds](https://www.airwallex.com/docs/api/payments/refunds/api)、[Stripe Refunds](https://docs.stripe.com/api/refunds/create)。
