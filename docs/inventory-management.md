# 商品与库存：第一阶段

入口：`/admin/inventory`。本阶段提供后台查询与配置，不向设备提交订单，也不改变现有 C 端套餐、支付或打印流程。

## 已实现

- 商品管理：查看供应商品牌 / 型号 / 壳体规格，关联现有 `PhoneModel`，维护展示名称和我方启用开关。新商品默认停用；机型映射不等于打印校准。
- 机型同步：选择设备后点击“同步所选设备机型”，从已同步的库存快照处理该设备全部现存商品，不受搜索 / 状态筛选影响。按品牌及 `型号` 规格匹配，缺少的品牌 / 机型自动建档；已有映射、名称覆盖、启用状态、旧索引和校准信息保留。新品牌 / 机型默认停用，机型 `print_ready=False`。重复同步不会重复建档。
- 供应商底图：机型管理提供“同步供应商底图”，按已映射商品下载尚未导入的图片；每个机型的“底图”抽屉展示各设备 / 款式的原图、原始像素尺寸、预览遮罩及错误状态。库存页引用同一份本地图片。原图保留 PNG 字节、色彩配置和分辨率元数据，不缩放、不推算打印 DPI。
- 设备库存：按设备 / 商品搜索，按缺货、低库存、过期筛选；展开查看各货道数量，商品汇总只统计货道快照，不叠加商品详情中的单货道库存。
- 设备管理：选择供应商连接登记设备，维护名称、位置备注、停用状态，手动同步库存。位置备注不是正式网点绑定。
- 连接配置：仅超级管理员可配置服务地址、商家与 Authorization；服务端复用已有加密能力，回显末四位。修改凭据不改变商品身份。服务地址 / 商家不可改，切换环境需新增连接。
- 同步记录：记录操作人、结果、时间和商品库存变化；这是快照差异，不是销售 / 补货流水。
- 操作审计：记录创建连接、登记设备、同步和人工配置修改，不记录凭据。

## 本地及部署准备

```sh
backend/.venv/bin/python backend/manage.py migrate
npm run admin
npm run backend
```

先由超级管理员新增连接，再登记设备，点击“同步库存”。凭据从配置界面输入，不放入命令行参数、文档或代码。

目前允许的 HTTPS 服务地址：`https://shop.widermatrix.cn`、`https://shop.autovendpro.com`。服务端不会跟随重定向发送凭据。

部署时须使用项目现有 `AI_CONFIG_ENCRYPTION_KEY` 的稳定值；加密配置不可用时不能新增 / 轮换凭据。不要为了新功能轮换这把主密钥，否则现有 AI、支付和设备凭据都会受影响。

库存同步命令：

```sh
# 参数为我方后台 Device 记录 ID，不是供应商设备编号
backend/.venv/bin/python backend/manage.py sync_device_inventory --device 1
backend/.venv/bin/python backend/manage.py sync_device_inventory --all
```

单次命令任一设备失败会返回非零退出码。`--all --watch --interval 300` 持续同步，失败后下一轮重试。`npm run backend` 同时启动本地 API 和同步进程并在退出时清理子进程；已有 API 进程可单独运行 `npm run inventory:watch`。dev 部署脚本会安装 `aicase-dev-inventory.timer`，每 5 分钟执行 `--all --allow-empty`；维护期间跳过，切换版本前停止旧同步进程。其他环境仍需部署同步服务或定时任务。API 同步在当前请求内执行，同设备有同步租约保护；反向代理 / 应用超时应留出至少 90 秒，后续大规模设备接入再改为持久任务队列。

## 设备列表与信息页

超级管理员可在「设备连接配置」点击「同步设备列表」，完整读取商家分页数据后登记设备；新设备默认停用，不覆盖已有名称、启用状态及位置。启用并同步库存后，从「设备管理 → 设备信息页」打开内嵌 H5。详见 [设备信息页](device-screen.md)。设备在线状态不从未定义的供应商状态码推断。

## 数据与权限

- 迁移：`0019_device_inventory`，新增连接、设备、供应商商品、设备商品、货道快照和同步批次表。
- 商品唯一键：本地连接 + `goods_id`；货道唯一键：设备 + 供应商货道记录 `id`。两类 ID 不混用。
- 供应商数据只读；可修改字段为本地机型 / 展示名称 / 开关 / 低库存阈值，以及设备名称和位置备注。API 拒绝库存等只读字段写入。
- 现有账号不会自动增加权限。超级管理员在“角色与权限”中给需要的角色分配“供应商商品 / 设备库存 / 设备管理 / 库存同步记录”权限。
- 同步使用独立的 `sync_device` 权限，不能仅凭查看或修改设备权限执行。连接凭据配置始终仅超级管理员可访问。
- 机型同步接口：`POST /api/v1/admin/inventory/products/sync-models/`，请求 `{ "device": 本地设备ID }`。需要查看设备、查看 / 修改供应商商品、新增品牌、新增机型权限；逐条映射及批次摘要进入操作日志。每次库存同步成功时，会作为系统同步流程自动创建缺失机型、关联已有机型；不新增用户权限，直接调用手动机型同步接口仍需上述权限。新机型及品牌默认停用，已有映射、启用状态和校准数据保留。自动关联与库存快照在同一事务发布，失败一起回滚；歧义型号保留库存并提示待确认。
- 底图导入接口：`POST /api/v1/admin/phone-models/{id}/import-template/`，请求 `{ "source": DeviceProduct主键, "refresh": false }`。需要查看 / 修改机型权限；校验商品确实映射至该机型。机型列表及详情通过只读 `template_sources` 返回底图来源与导入状态，公共机型接口不暴露这些后台来源。
- 迁移 `0020_supplier_template_assets` 在设备商品上保存导入来源、文件路径、像素尺寸、时间、错误及遮罩说明。文件存于 `MEDIA_ROOT/supplier-templates/`，部署需持久保存媒体目录；使用现有 `/media/` 文件服务，无需运行用户端开发服务器。
- 库存超过 15 分钟标记过期；最近快照、设备启用状态都不等于设备在线可打印。供应商在线状态未明确前不展示虚假的“在线”。

## 同步保护与当前限制

- HTTP 成功后仍校验业务 `code=200`；401、网络错误、非法数据、归属不符、重复货道、同商品规格 / 价格冲突均不发布该批库存。
- 空列表、货道记录减少暂按异常处理，保留原快照并提示核实。当前没有“确认清空 / 移除货道”功能，需设备方明确完整列表 / 删除语义后实现；不能把旧快照当现存库存保证。
- 同设备禁止重叠同步；超过 3 分钟可由新批次接替。凭据 / 设备配置在同步期间变化，旧批次不发布；发布失败事务回滚，旧库存不变。
- 商品编号对应的产品 / 规格发生变化时，暂停发布并提示核实，避免覆盖人工机型对应关系。
- 模板优先使用货道来源值，其次保留已有 URL；缺失时从商品详情补齐，4 路并发、有限时间内尝试。补齐失败不阻塞已验证的库存，提示“模板待补充”，下次同步继续尝试。已有模板的更新检查、版本审核和生产校准属于后续阶段。
- 自动机型识别当前支持 iPhone / Apple、Samsung、Xiaomi（含明确标注的 Redmi / POCO 系列），规范空白、不可见字符和大小写，但保留 `+`、4G / 5G 等区别。以具体型号规格为准，不用产品系列名替代型号。缺失规格、未知格式、重复候选、系列冲突均跳过并展示原因。普通 / 磁吸壳商品仍独立，只共用机型。供应商模板 URL 不会自动进入已审核的模板注册表；非苹果新机型的预览类型暂为通用示意壳，需后续配置真实模板。
- 底图导入仅允许 `oss.widermatrix.cn`，HTTP 升级为 HTTPS；不携带设备凭据、不跟随跳转。限制 10 MB、4096 边长、800 万像素、单帧 PNG 及下载时间。文件校验后按内容哈希保存；导入失败保留旧图，来源地址变化后旧图不再作为当前模板展示。发布时再次核对机型映射与来源。
- 预览遮罩仅从底图中心连通且封闭的透明区域生成，排除相机与边框；不透明中心、边缘泄漏、过小区域均保留底图并提示补充独立遮罩。该遮罩不是设备方确认的打印范围，不设置 `print_ready`，也不覆盖当前用户端的两套模板。全量导入在浏览器逐项执行并显示进度，失败后可重新同步；单项“重新获取底图”可检查相同 URL 的新内容。
- 供应商币种为空时显示“币种未提供”，来源价格不覆盖 `PricingPlan`。不创建库存预占，不在本地扣库存。
- 尚未提供正式网点模型、模板版本审核、补货 / 盘点写入、设备在线检测、C 端商品目录、打印派单和出货回调。后续见根目录 `TODO.md`。

## C 端库存目录

- 用户端机型选择读取 `GET /api/v1/store/phone-models/`，不再使用固定两机型作为可选列表。无设备参数时显示所有已配置设备中的可用机型；`?device_id=401&shop_id=146` 按供应商设备 / 商家限定，未知设备返回空列表，歧义编号拒绝请求，不回退其他设备。
- 显示条件：连接、设备、设备商品、供应商商品、机型、品牌均启用；库存大于零；成功发布的快照未超过 15 分钟（同步进行中或一次刷新失败，不撤下仍有效的快照）；底图和遮罩齐全且对应当前来源。多设备同机型去重，各商品库存不互相替代。
- 正常每分钟、进入选择页和继续确认设计前刷新目录。库存过期返回 updating 状态，与缺货分开；更新中 / 请求失败时每 10 秒自动重试并保留已选机型及设计内容，恢复后重新核对；不回退静态机型。已选择机型缺货后需重新选择，服务器在保存订单时再次检查对应商品及模板版本，不做库存预占或本地扣减。
- 供应商底图以原始像素用于 C 端预览，未设置推算 DPI。新订单固定保存后端核验的模板版本和来源商品，库存变化、停用或模板更新后，历史订单仍使用原始文件。新模板只开放预览，后台真实打印文件仍需明确输出参数，支付和设备派单未在本阶段改造。
- 2026-11-02 根据用户明确授权，在本地启用设备 401 下有库存且底图 / 遮罩齐全的 50 个商品与机型，保留打印校准标记原值。用户端已验证 Samsung S25+ 底图及订单确认页面；未操作真实支付或打印。
- 部署需持续执行库存同步命令（建议每 5 分钟一次，按供应商允许频率）；本地自动同步已随启动命令接入；dev 的定时任务会随包含该变更的版本部署安装；尚未部署该版本或其他环境未配置调度时，需要手动同步，长时间不刷新会按上述有效期隐藏机型并提示待更新。
