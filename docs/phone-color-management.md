# 机型颜色管理（本地开发，待完整验收）

颜色是可选的机身预览配置。RGB 是近似显示色，不是实物测色；颜色不代表供应商壳体 SKU、库存、模板可售或打印校准。目前提供后台管理及显式参考初始化操作；初始化仅在新建隔离测试库中执行过，用户现有数据库未初始化。用户端选色与服务端订单颜色快照已在本地接入，仍待浏览器及像素验收。

## 入口与权限

后台沿用 `npm run admin`，可复现地址为 `http://127.0.0.1:5173/admin/phone-colors`；也可从「机型管理」每行「颜色」进入对应机型。需要另行运行隔离本地 API，不要为此修改用户现有数据库。此次没有常驻预览进程或部署。

超级管理员在「角色与权限 → 机型颜色」分配独立的查看、新增、修改、人工核验权限。机型修改权限不自动获得颜色权限。上传需要颜色查看和修改权限；核验还需要 `verify_phonecolor`。所有写接口沿用后台会话和 CSRF 校验。为保存历史资源和引用，不提供删除接口；不需要的颜色可停用。

1. 选择现有机型，新增稳定编码、辅助名称及 RGB。编码在每个机型内唯一，创建后不能修改或迁移机型；RGB 恰好包含三个 0–255 整数，不能缺项、使用字符串、布尔或小数。取色器换算 RGB，HEX 不另存。
2. 配置来源、区域／网络／特别版备注、排序及默认项。每个机型至多一个默认项，调整默认项先取消原项。新颜色默认停用，空态明确颜色可选。
3. 保存草稿后，选择当前机型已有的模板版本并同时上传机身覆盖图和遮罩。只接收文件，不接受素材路径、远端地址或客户照片。真实解码单帧 PNG，每张最多 10 MB、32–4096 px、800 万像素；两图须与绑定模板原始像素尺寸相同，均须至少 1% 全透明及 1% 全不透明区域。去除上传元数据后重新编码，按随机目录保存；记录 SHA-256、模板、尺寸、版本及上传人。
4. 打开当前资源链接检查实际图片、授权、尺寸和透明范围，填写核验说明并核验当前整数版本。服务端再次读取、验哈希和解码，拒绝缺失、篡改或模板失效的资源。核验本身不会启用颜色。
5. 单独启用并保存。启用时再次检查当前资源及核验状态；缺资源允许保存停用草稿，拒绝启用。替换上传会新增版本、保留旧版本和旧核验，自动停用当前颜色并清除当前核验状态；过期核验请求不能核验新版本。

后台支持刷新读取、近似色块、取色器及 RGB 输入、排序／默认／启用、资源链接预览、版本与核验信息。未提供浏览器自动核验或真机校准功能；目录会重新复核资源并隐藏失效颜色，原机型可售筛选不变；历史订单保留冻结颜色和资源版本。

## 接口与存储

- `GET /api/v1/admin/phone-colors/?phone_model=<id>`：分页列表；筛选 ID 仅接受 ASCII 十进制正整数，范围为 1–9223372036854775807；非法、超范围或超长参数返回 400 及参数说明，范围内不存在的 ID 返回空列表。`POST` 创建停用草稿；`GET/PATCH .../<id>/` 查看和修改。
- `GET .../phone-colors/options_catalog/`：颜色权限下的现有机型与本地模板版本选项，包含已导入但尚不可售的供应商模板，不执行外部请求。
- `POST .../<id>/resources/`：multipart `overlay`、`mask`、`template_id`，必须同时上传。
- `POST .../<id>/verify-resources/`：JSON `version`、`review_note`，绑定当前资源版本。
- `GET .../initialize-reference/`：只读预览全库匹配、逐项颜色／来源／备注及预计新增、已有、未匹配、歧义、待确认统计，需要颜色查看权限。
- `POST .../initialize-reference/`：仅接受预览返回的 `reference_sha256` 和布尔 `confirm=true`，需要颜色查看与新增权限及 CSRF。重新按当前数据库匹配，只新增停用草稿；返回实际统计。参考文件内容变化返回 400 要求重新预览，不接受提交路径、URL、颜色清单或自动启用参数。
- `PhoneColor` 与 `PhoneColorResource` 由迁移 `0034_phone_color_previews` 增量建立；没有数据初始化、历史重算或旧表覆盖。资源存于 `MEDIA_ROOT/phone-colors/<随机标识>/`，仅用于合法公开预览素材。
- 新增、修改、上传、核验记录在原操作日志；上传和核验日志记录版本及动作，不记录图片内容或访问密钥。数据库约束兜底机型内编码、默认项和资源版本唯一；写入锁定所属机型，避免同机型并发写入造成默认项和版本冲突。PostgreSQL 并发行为仍需独立测试。

## 参考颜色初始化（开发交付待独立验收）

1. 仅在经授权的目标数据库操作。本任务开发／验收必须新建隔离数据库，不得使用用户数据库或已有调试副本。后台打开「机型颜色 → 预览初始化」，这是只读操作，不受页面当前机型筛选限制。
2. 唯一输入是仓库 `backend/management_api/seed/phone-color-reference.json`，共 50 款，其中 44 款已核实、218 条颜色，6 款待确认。逐项检查实际匹配结果、候选机型 ID、待确认原因、RGB、区域／网络／特别版备注及来源。展开的颜色是参考值，已有配置不会被参考值替换。
3. 只有品牌名称和机型名称均精确一致且仅有一个候选时才可导入。区分大小写、空格和网络型号，不做模糊匹配或别名推断；歧义、未匹配及待确认均跳过，不创建机型。机型启用、库存可售和模板有效性不作为资料草稿导入的条件，也不会被导入操作修改。
4. 点击「确认仅新增停用草稿」。服务端重新检查当前数据库，按机型及稳定颜色编码跳过已有项；已有名称、RGB、排序、默认、启用、来源、备注、资源及历史版本全部保持。新项保留完整来源和特别版备注，全部停用、非默认、无资源，不猜测共用模板。初始化本身不获取外部图片或调用供应商。
5. 执行结果显示实际新增／已有等统计。可以重新预览并再次执行，零新增仍记录执行审计；超时后先重新预览核实，不自动重发。相同机型锁与正常管理写入互斥；整个导入和审计在一个事务内，失败整体回滚。每个新增项写审计，批次审计保存资料完整 SHA-256 和统计，重复执行不会覆盖人工改动。

新增回归使用合成机型，在 Django 全新内存数据库实际执行两次全量导入；覆盖 218 项新增及第二次 218 项已有、6 款跳过、人工修改／资源保留、匹配歧义／品牌与大小写／空格不匹配、预览后数据变化、摘要变化、非法输入、权限、CSRF 及审计失败回滚。尚无真实后台浏览器和 PostgreSQL 并发证据，也未初始化用户现有数据库。

## 用户端颜色与订单契约（开发交付待独立验收）

- 有效用户端 `npm start` → `http://127.0.0.1:4173/#choose`；后台入口不变。需另启新建隔离库的 API，不得使用用户旧数据库或旧 direct_debug 副本。本轮没有常驻服务、部署或浏览器通过证据。
- 公开库存目录 `models[].colors` 为空时不显示选色，仍可继续原可用机型；不会用参考清单、固定四色、默认蓝色或上一个机型颜色补齐。只有已启用且已核验、文件和当前模板仍有效的颜色可显示；`rgb` 绘近似色块，`resource` 提供真实覆盖图／遮罩、模板、尺寸和版本。
- 选色使用有效默认项或排序首项；修改配置后刷新目录可见。资源替换、停用或模板变化后，本机草稿恢复清理旧选择并提示重新预览，本机已保存记录及订单快照保留原样。源素材不得删除，以维持历史预览。
- 建单／可编辑设计快照新增可选 `phoneColor={code,version}`；服务端按当前有效颜色解析并冻结名称、RGB 和资源，不接受客户端指定素材路径／RGB。缺省仍兼容无颜色请求。历史订单不随配置变化重算金额、颜色、图片或履约状态。
- 已付款订单首次明确确认其他设备模板时，不增加颜色 SKU／库存限制。原颜色快照继续保留；不匹配该模板的颜色不会绘入新预览，手机显示基础预览和双语说明，不猜色或替换历史快照。
- 机身覆盖图和颜色遮罩只影响预览；原始打印与供应商打印使用绑定模板像素及原打印遮罩。开发自测仅验证真实导出函数的资源加载与尺寸，真实浏览器像素、打印校准、后台初始化抽屉与 PostgreSQL 并发仍待独立测试。
