## 使用与状态

1. 选择 iPhone 17 或 iPhone 16e，上传照片并选择 AI 风格。
2. 确认页左侧为实际原图，右侧标记为风格参考。勾选确认并生成后，原图才发送至后台及 OpenAI。
3. 后台保存任务和英文提示词快照，预留一次额度，立即返回任务编号；独立进程执行图片编辑。前台每 3 秒查询进度，关闭页面不终止任务，回到同一浏览器可恢复。
4. 成功后加载私有结果，点击“Use this look on my case”应用到手机壳，可继续裁切、移动、叠字、切换两种模板，再进入报价确认。
5. 失败或排队取消返还额度。开始生成后不允许取消；不自动重发图片请求。超过 10 分钟的中断任务转为失败。重试需要再次确认。

旧演示任务保留原图并提供重新生成入口；不再提供把样片冒充上传照片转换结果的操作。图库中的多效果排版仍作为风格参考。

## 接口与约束

- `GET /api/v1/store/ai-account/`：服务端免费体验及月度额度。
- `POST /api/v1/store/ai-account/`：仅本地 DEBUG 环境允许模拟订阅、停止/恢复续订。
- `POST /api/v1/store/ai-renders/`：`request_key`、`accepted`、`photo`、`style_id`、`model`。同一请求标识重发不会重复扣次或生成，冲突内容拒绝。
- `GET /api/v1/store/ai-renders/<id>/`：状态；POST 只支持取消未开始任务。
- `GET /api/v1/store/ai-renders/<id>/image/`：PNG 结果，仅原浏览器访问令牌可读取。

以上接口使用已有的 `X-Order-Key` 浏览器访问令牌，只存散列。结果及原图存于私有数据库，当前版本在任务结束时设置原图与结果的共同到期时间，之后按期限清理；不暴露为公共素材链接。浏览器保存编辑用的生成结果副本。不要清除站点数据，否则将失去该浏览器的任务访问权。

真实请求固定为 `POST https://api.openai.com/v1/images/edits`，multipart 上传原图，使用后台选定模型，输出 `1024x1536`、medium、PNG。API Key 只在服务端解密，不发送前端，也不随重定向转发。风格提示词和机型构图要求在后台组合；不采用与案例人物绑定的样片制作说明去替换顾客主体。生成原图尺寸与最终 300 DPI 模板导出尺寸是两回事；打印位置仍需供应商打样确认。

## 运行与验证

先执行迁移 `0008_aiaccount_airender`，正常启动现有 Django 服务即可。任务由同一 Python 环境的 `run_ai_render` 子进程处理，无需浏览器持续连接。默认限制每 24 小时最多 20 个新任务、最多 2 个并发，可通过 `AI_DAILY_RENDER_LIMIT`、`AI_CONCURRENT_RENDER_LIMIT` 调整。

服务端免费体验按浏览器令牌计数，支付仍为模拟。正式上线前需要真实用户认证、支付校验及共享限流/可靠队列；当前能力用于本地联调，不构成生产计费系统。部署时不要只发布前端，应同时迁移并发布后台。

自动测试覆盖任务幂等、服务端额度、私有图片访问、失败返还、超时恢复、唯一执行、真实 multipart 原图请求、上游错误脱敏、前端状态恢复逻辑、原图/参考图/结果的区分及订单中的 live 来源标识。

本地真实联调进行了两次：第一次返回 HTTP 429，完善错误分类后再次确认错误码为 `credit_balance_exhausted`（OpenAI API 预付余额耗尽）。两次任务均正确显示失败并返还体验次数，未得到可用于验证画质的真实结果。“检查连接”仅读取模型信息，成功不代表余额或图片接口限额可用；后台配置页将单独显示最近一次真实生图结果。沿用用户已保存的 Key 与模型，未修改账号计费设置。补足 API 余额后，可在前台重新确认生成。

接口依据：[OpenAI 图片编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)、[错误码说明](https://developers.openai.com/api/docs/guides/error-codes)。
