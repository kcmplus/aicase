# POPOMO 消费者营销交互

更新：2026-10-17。依据项目根目录 `技术交付文档/营销模块需求记录.md`。本次落地消费者领券与交易闭环；内部运营需求继续保留到未来 PRD，前台没有后台模式。

## 入口和体验

- 首页保留手机壳创作主视觉，在图案库前增加次要“创作礼”入口；已有机型时可继续设计。
- 顶部、菜单和登录后的账户窗口均可到达活动或钱包。
- `#offers` 领取优惠、展开规则并继续创作；`#offers?tab=wallet` 展示当前本机演示账户的可用、已使用、过期或不满足首单条件的券。
- 设备页有活动入口；使用 SH-001 设备券仍须确认所选机型受支持且有库存。
- 单壳与合并购物车结账均支持主动选券、不可用原因、原价/抵扣/应付；选券不清除地址或确认状态。
- 成功订单保存独立的优惠和来源快照，已使用的券可跳转对应订单。
- 活动页可复制公开活动链接，仅含语言、活动 ID、来源，不含照片、个人设计或账户资料，不自动发送给任何人。

## 演示参数，不是正式商业政策

| 券 ID | 示例金额 | 条件 |
| --- | --- | --- |
| `welcome` | USD 5 | 当前本机演示账户首笔订单，含定制手机壳，邮寄或现场打印均可。 |
| `station` | USD 6 | SH-001 现场打印，机型支持且有库存；购物车邮寄不适用。 |
| `shipping` | USD 3 | 抵扣有运费的邮寄订单，手机壳、配件和合并邮寄均可。 |

统一示例：领取后 7 × 24 小时有效、每个本机演示账户每种限领一次、每单最多一张、不叠加、不自动勾选，无额外金额门槛。按领取时间精确判断过期；券面显示到期日期。退款返券、重新领取、预算、正式门槛待 PRD，不直接沿用演示参数。

保留手机壳 USD 69、运费 USD 8：新客邮寄 77 − 5 = 72；指定设备 69 − 6 = 63；运费券邮寄 77 − 3 = 74。手机壳加 USD 12 挂绳统一邮寄 89，运费券后 86。配件不能从设备取货，不引入一次支付拆成取货和邮寄。

## 状态与技术契约

`marketing-core.js` 管理定义、领取、资格、报价、核销和来源。状态在原有 `ai-case-studio-v1` 本地存储中，无营销服务请求。

- `marketing.wallets[email]` 保存各账户的领取时间、到期时间、使用订单 ID；切换账户不混券。
- `marketing.selected[email]` 保存主动选择的一张券。未选按原价；不适用时显示原因，需改选或明确不使用后才能支付。
- 领取首单券与结账均检查历史订单；新订单保存 `ownerEmail`。没有账户字段的旧订单保守视作本浏览器已有成交，因此不满足首单条件；正式首单认定仍待 PRD。
- 用整数美分计算抵扣，不超过对应商品/运费金额；原商品与运费分别保留，优惠单列。
- 支付保存提交快照，提交前及模拟成功时重新判断资格和金额。失败不新增订单、不核销券、不清空购物车。
- 成功订单保存 `subtotal`、`shipping`、`originalTotal`、`discount`、`total`、`ownerEmail`、`marketing.coupon`、`marketing.attribution`。后续更换设备、语言、账户、券不会改变历史成交金额。
- 本机账户无真实认证，本地数据可被浏览器用户修改；正式系统须由服务端报价、校验、原子核销并处理并发，不以本地演示替代生产安全。

## 活动来源

示例：`?device=SH-001&campaign=station-moment&source=station#device`。扫码继续自动读取默认机型；库存不足改邮寄时保留来源，但设备券资格失效。

仅在 URL 明确含有效 `campaign` 和允许的 `source` 时更新来源。来源允许 `home`、`station`、`menu`、`partner`、`direct`；活动 ID 为 1–48 位字母、数字或连字符，设备 ID 校验为 `SH-` 加三位数字。普通导航、语言切换、换设备或改邮寄不会覆盖已有来源。

首页/设备活动入口在本机记录来源；公开复制链接使用 `source=partner`。当前只是本浏览器“最近一次明确活动入口”示例，无正式归因窗口、第三方埋点或外部发送。订单复制来源快照，实际交付方式独立保存。渠道二维码管理、广告/达人归因、真实事件收集和内部报表仍待实施。

没有上线真实发券、真实支付、营销消息、后台、积分、推荐奖励或佣金。实物壳体照片等待提供。现有可选配件入口保留，无预选加购；后续 PRD 保留其余已确认营销方向。

多页面回归：同浏览器标签页共享订单和领取/核销记录；付款最终提交用 Web Locks 互斥，并重新读取本地记录。没有 Web Locks 的浏览器无法带券模拟支付，可换新版浏览器或不用券。普通保存合并已有订单与已用券，保留其他页面成交记录；不覆盖当前草稿和地址。来源参数在首次捕获后从地址栏消费掉，避免切换设备后刷新被当作新活动入口。
